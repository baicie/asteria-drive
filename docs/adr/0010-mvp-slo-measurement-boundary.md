# ADR-0010: MVP 暂定 SLO 测量分阶段边界

- 状态：Accepted
- 日期：2026-08-02
- 范围：P4 验收中的控制面性能与并发基线
- 修订：[scope.md](../mvp/scope.md) §9、[acceptance.md](../mvp/acceptance.md) AC-080

## Context

scope §9 给出了包含「Namespace 最多 100 万活动节点、持续采样至少 10 分钟」等条件的暂定 SLO。
当前隔离开发机可以稳定运行 PostgreSQL + SeaweedFS 主路径与 100 并发上传会话，但不具备可复现的
百万节点数据装载与长时压测夹具。若坚持把未测量的规模目标算作 MUST，会迫使团队要么虚报完成，
要么无限期阻断本已可用的垂直切片验收。

## Decision

1. **MVP MUST 性能门槛**（本轮必须有证据）：
   - 内存 fake 上的控制面烟雾基线：`healthz` / 租户发现 / 目录列表 / 分片签名的本地 p95 上限可复现；
   - 真实 PostgreSQL + SeaweedFS 上至少 100 个并发上传会话的创建、签名与查询，无串租户、无重复会话 ID、
     未提交文件不进入 Namespace；
   - 上述运行中无非预期控制面 `5xx`。
2. **规模化暂定 SLO**（百万节点、长时多端点负载报告）保持为 **SHOULD**：延期到具备专用性能环境的
   后续迭代，并在验收记录中保留已测样本与偏差说明。
3. scope §9 中的数值仍作为后续压测目标，不删除；但不得在没有百万节点证据时勾选「已满足全部暂定 SLO」。

## Consequences

- P4 可以用真实主路径 + 100 并发 + 烟雾基线关闭 MVP 发布门槛，而不假装完成百万节点压测。
- 对外沟通必须区分「MVP 验收候选」与「规模化性能达标」。
- 后续若恢复 AC-080 为全量 MUST，需先建设可复现装载/压测夹具并更新本 ADR。

## Rejected alternatives

- **虚报 AC-080 全量通过**：破坏证据纪律。
- **因百万节点未测而阻断全部 MVP**：与「先证明垂直切片」的目标不成比例。
- **删除 scope §9 目标**：丢失后续压测锚点。
