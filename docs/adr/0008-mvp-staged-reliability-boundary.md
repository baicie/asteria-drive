# ADR-0008: MVP 创建幂等与维护任务的分阶段交付边界

- 状态：Accepted
- 日期：2026-08-02
- 范围：MVP 候选版本的创建幂等、过期处理与垃圾回收
- 修订：ADR-0001、ADR-0006 的阶段性实现要求

## Context

ADR-0001 把同进程维护循环写入 MVP 部署边界，ADR-0006 又把创建上传会话的
`Idempotency-Key` 写成强制要求。后续 scope 和验收设计把二者调整为 SHOULD，而上传完成幂等、手动取消
和手动永久清理仍是 MUST。当前实现已经提供上传完成摘要幂等与同步清理路径，但尚未提供创建请求去重、
租约式过期扫描和独立 GC 循环。

若继续把未实现的 SHOULD 描述成已交付强制语义，客户端会错误地依赖请求去重，运维也会误以为过期会话
和失败清理可以无人值守。为保持候选版本契约真实，需要明确分阶段边界，同时不能削弱数据一致性要求。

## Decision

1. 上传完成继续以上传会话 ID 与规范化 completion digest 作为 MUST 幂等边界。相同清单重试返回同一
   文件结果，不同清单返回 `idempotency_conflict`，不得创建第二个节点、版本或 Blob。
2. 创建目录和创建上传会话的 `Idempotency-Key` 在本轮保持 SHOULD。实现并完成持久化保留期、请求摘要
   和冲突测试之前，HTTP 契约不声明支持该 Header；客户端必须通过读取资源、处理 `name_conflict` 和
   自身请求关联来收敛未知结果。
3. 手动取消上传、手动回收/恢复和手动永久清理仍是 MVP MUST。自动扫描过期上传、回收保留期清理、
   孤儿对账和租约式重试循环保持 SHOULD，未实现时必须在运行文档与验收记录中列为开放风险。
4. 没有维护循环时不得声称具备无人值守生命周期收敛能力。真实 PostgreSQL + S3 失败窗口、重复清理和
   引用保护仍必须在 MVP 完成前验证；若这些 MUST 无法通过，不能用本 ADR 降级为后续工作。
5. 后续引入 `Idempotency-Key` 或维护循环时，应先冻结持久化 Schema、保留期、租约、批次、重试退避、
   指标和停机语义，并补齐契约/故障注入测试；不要求因此拆出独立 Worker。

## Consequences

- 当前 OpenAPI 不会承诺尚未实现的创建去重语义。
- 服务重启或客户端超时后的创建请求可能产生 `name_conflict`，调用方需要读取当前 Namespace 再决定动作。
- 过期 Multipart 和失败对象删除可能暂时占用存储，需要人工检查和保守处理，不能依赖自动后台收敛。
- 本轮仍保留强制的完成幂等、租户隔离、不可变 Blob 和引用保护，不扩大公网或生产适用范围。
- M2 的 Outbox/独立 Worker 不是实现上述维护任务的前置条件。

## Rejected alternatives

- **把未实现行为保留在公开契约中**：会让文档与可观察行为不一致，并诱导客户端错误重试。
- **为了关闭文档缺口仓促增加进程内定时器**：缺少租约、批次、指标和故障测试时，多实例运行可能重复或
  错误清理。
- **取消上传完成幂等要求**：对象存储与 PostgreSQL 的双写窗口使“只调用一次”不可成立。
- **把全部维护工作推到独立 Worker 后才处理**：微服务拆分不是幂等维护的必要条件，会扩大 MVP 依赖。

## Follow-up or triggers

- 创建请求重试成为真实客户端的高频故障时，优先交付持久化 `Idempotency-Key`，并更新 OpenAPI。
- 在任何长时间运行或共享验收环境启用前，补齐过期会话扫描、Abort 重试、孤儿对账和可观测积压。
- 引入多实例维护执行时，必须增加数据库租约或等价互斥，并验证停机接管和至少一次执行语义。
