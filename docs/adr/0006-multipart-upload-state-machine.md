# ADR-0006: Multipart 上传状态机、幂等与孤儿回收

- 状态：Accepted
- 日期：2026-08-02
- 范围：上传协调、一致性与生命周期

## Context

客户端需要并行、断点续传和分片重试，但对象存储与 PostgreSQL 不能参与同一个分布式事务。对象完成后数据库可能提交失败，数据库会话也可能在客户端中断后长期遗留。重复请求、并发完成、网络超时和维护任务重试都可能导致重复版本或孤儿对象。

## Decision

每次上传先在 PostgreSQL 创建租户作用域的 `upload_session`，并使用显式状态机：

```text
CREATED -> UPLOADING -> COMPLETING -> OBJECT_COMPLETED -> COMMITTED
    |          |              |              |
    +----------+--------------+--------------+-> ABORTED / EXPIRED / FAILED
```

`COMMITTED`、`ABORTED`、`EXPIRED` 和不可重试的 `FAILED` 是终态。状态转换使用版本号或条件更新；同一会话只有一个完成者，超时租约可被安全接管。服务端在签发 URL 前完成租户与父目录检查，并强制服务端文件大小上限。M2 引入配额时，必须在创建会话时原子预留、提交时转为已用、取消或过期时释放，不能改变状态机和幂等边界。

原始决策要求创建接口使用 `Idempotency-Key`：键按租户、主体和操作作用域保存，并绑定规范化请求摘要，
相同键和相同请求返回原会话，相同键但不同请求返回冲突。ADR-0008 将该要求调整为本轮 SHOULD，实装前
不进入公开 HTTP 契约。分片记录以 `(upload_session_id, part_number)` 唯一，重复上报必须具有相同
ETag/Checksum；完成请求保存有序分片摘要，重复完成返回同一提交结果，不创建第二个版本。

完成流程为：

1. 条件更新到 `COMPLETING` 并冻结分片清单；
2. 调用 `StorageProvider` 完成 Multipart，并校验对象存在、大小和可用 Checksum；
3. 记录 `OBJECT_COMPLETED`；
4. 在一个 PostgreSQL 事务中创建 Blob、节点和版本，更新当前版本并把会话转为 `COMMITTED`；该事务以上传会话 ID 建立唯一提交约束；M2 的配额结转和 Outbox 必须加入同一事务；
5. 读取并返回已提交结果；事务结果不明或请求重试时，先按会话 ID 查询并返回同一结果。

若对象完成但数据库事务失败，会话保留为可恢复的未提交状态；协调器重试“检查对象并提交元数据”，而不是再次生成版本。过期维护任务中止未完成 Multipart。孤儿 GC 只处理超过宽限期的会话或对象：删除前再次确认没有已提交 Blob 引用，以租约阻止与提交并发，执行幂等删除并记录指标。定期对象清单对账用于发现数据库记录之外的遗留对象，但不在用户请求路径执行。

## Consequences

- 客户端可安全重试创建、分片上报和完成请求，网络超时不会自然演变为重复文件版本。
- 本轮用服务端单文件上限控制风险；正式计费或公网发布前必须补齐配额预留，不能把文件上限冒充配额。
- 状态机和恢复流程比简单“上传成功即写文件表”复杂，需要故障注入和后台巡检。
- 对象完成与元数据可见之间存在短暂窗口；只有 `COMMITTED` 文件对用户可见。
- GC 必须保守，宁可暂时泄漏存储，也不能误删可能提交或仍被引用的对象。

## Rejected alternatives

- **让 PostgreSQL 与对象存储做 XA/两阶段提交**：主流 S3 接口不支持，复杂度也不可控。
- **客户端上传成功就视为文件已提交**：绕过租户检查、版本与元数据一致事务。
- **失败后立即删除对象**：可能与迟到的重试或数据库提交竞争，造成数据丢失。
- **依赖请求天然只到达一次**：网络与 Worker 都只能现实地提供至少一次调用语义。

## Follow-up or triggers

- 归档上传 API、状态转换表、幂等键保留期、分片限制、会话 TTL 和 GC 宽限期。
- 为每个外部调用点补充崩溃、超时、重复请求、大小不符和 GC/提交竞态测试。
- 当小文件开销成为瓶颈时，可增加单次 PUT 快速路径，但必须复用同一授权、幂等和提交语义。
