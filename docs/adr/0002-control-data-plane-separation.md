# ADR-0002: 控制面、数据面分离与对象存储直传

- 状态：Accepted
- 日期：2026-08-02
- 范围：上传、下载与网络数据路径

## Context

文件内容可能从 KB 增长到 GB 或 TB。如果普通业务服务代理全部字节流，其网络带宽、连接数、内存和故障域会成为系统吞吐瓶颈，也会让 API 扩容成本随存储流量线性增长。网盘核心真正需要拥有的是身份、权限、目录、版本、配额和审计，而副本、纠删码、Range 和磁盘恢复应由成熟对象存储承担。

## Decision

系统明确分为两个平面：

- **控制面**：Asteria API 处理身份和租户校验、ACL、目录与版本、配额、上传会话、分享和审计，并签发短期数据面凭证。
- **数据面**：客户端使用受限的预签名 URL，直接与 S3-compatible 对象存储或 CDN 进行上传、下载、Range 和 Multipart 传输。

普通文件字节不得经过 `asteria-server`。上传 URL 只允许指定对象、方法、分片和短期有效期；下载授权决策记录主体、租户、节点、版本和策略，生成的 URL 只授予对应对象的短期读取能力。对象 Key 由服务端生成，客户端既不能选择 Key，也不能从用户路径推导 Key。

上传只有在对象完成且元数据事务提交后才对用户可见。控制面不可用时不能创建新会话或签发新授权；已经开始的数据面传输可在现有签名有效期内继续，不承诺立即撤销已签发的 URL。

需要水印、实时转换、服务端解密、DLP 或强制逐字节审计时，使用独立且显式的受控代理路径，并通过后续 ADR 说明成本和安全边界；它不是普通下载的回退路径。

## Consequences

- API 主要处理 KB 级控制请求，文件吞吐可随对象存储和 CDN 独立扩展。
- 数据传输不会因某个 API 实例重启而中断，但签名过期、对象存储故障仍会影响传输。
- 客户端需要实现 Multipart、重试、Checksum、CORS 和签名刷新，协议复杂度增加。
- 短期 URL 是持有者凭证，日志、跳转页和客户端不得泄露；签名 TTL 必须在可恢复性与撤销窗口之间取舍。
- API 指标不能直接代表实际传输完成率，需要同时采集对象存储、客户端和协调器指标。

## Rejected alternatives

- **由 Go 服务代理全部上传下载**：形成带宽和连接瓶颈，扩大应用故障影响面。
- **公开 Bucket 或长期对象 URL**：无法可靠执行授权、过期、撤销和审计边界。
- **客户端直接持有对象存储长期凭证**：权限过宽，泄露后的影响难以收敛。
- **使用对象存储 ListObjects 作为目录 API**：对象 Key 不是用户 Namespace，无法承载版本、ACL 和事务语义。

## Follow-up or triggers

- 分别设计创建上传、签发分片、完成上传、下载授权和 Range 下载协议。
- 在端到端测试中验证签名范围、TTL、CORS、Content-Disposition、Checksum 和越权失败路径。
- 引入 CDN、企业受控代理或即时撤销要求时，新增 ADR 说明缓存、密钥、审计和故障语义。
