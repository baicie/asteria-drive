# 需要避免的设计

> 状态：长期约束。来源为产品蓝图；与 MVP 实现纪律一致。

不要：

1. 让 Java/Go/Node 服务代理所有文件流量。
2. 将完整用户路径直接作为对象存储 Key。
3. 每次重命名都复制对象。
4. 第一阶段就做全局块级去重。
5. 使用 Redis 保存最终文件状态。
6. 上传成功后同步执行预览和扫描。
7. 第一阶段拆成大量微服务。
8. 为了“自主可控”自己实现副本、纠删码和磁盘恢复。
9. 把对象存储中的 `ListObjects` 当作网盘目录查询。
10. 只备份 PostgreSQL，却不验证对象和元数据是否可以联合恢复。

关键不是使用最多的组件，而是让文件字节走最短的数据路径，让复杂度集中在真正属于网盘产品的
元数据、同步、版本和权限系统中。
