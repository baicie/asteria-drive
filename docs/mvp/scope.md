# 后端 MVP 范围

> 状态：MVP 范围基线。本文使用 MUST、SHOULD、NOT NOW 表示优先级；具体实现与验收状态见
> [implementation-log.md](implementation-log.md)。

## 1. 问题与目标

Asteria Drive 需要先证明网盘产品层最关键的一条链路可以正确闭环，而不是在首期同时建设同步客户端、
协作、搜索、预览和微服务平台。本 MVP 的目标是交付一个 Go 模块化单体控制面，以 PostgreSQL 作为
元数据真相源，以 S3 兼容对象存储作为数据面，并保证文件字节不经过普通业务 API。

成功路径如下：

1. 调用方使用服务端预配置的受信任开发 Bearer Token 建立租户和主体上下文。
2. 调用方创建目录并用游标列出目录内容。
3. 调用方创建上传会话，获取 S3 Multipart 分片签名 URL。
4. 调用方直接把文件分片上传到 SeaweedFS/S3 兼容对象存储。
5. 调用方提交分片清单；服务端完成对象并在一个数据库事务中创建 Blob、文件版本和文件节点。
6. 调用方请求短期下载授权并直接从对象存储下载。
7. 调用方把文件或目录移入回收站，之后恢复或永久清理。

## 2. 架构边界

```text
HTTP API / 模块化单体（控制面）
  auth boundary
  namespace
  upload
  download
  recycle
  application services
         |                         |
         v                         v
MetadataRepository port      ObjectStorage port
  |              |             |             |
PostgreSQL   in-memory fake   S3 adapter   in-memory fake
                                  |
                              SeaweedFS/S3

客户端 ---------------- 文件字节 ----------------> 对象存储
```

约束：

- 模块可以在同一进程、同一仓库中协作，但只能通过明确的应用服务和 port 交互。
- PostgreSQL 是租户、节点、文件版本、Blob、上传会话和回收状态的真相源。
- 对象存储只保存不可变内容，不能使用 `ListObjects` 代替目录查询。
- 对象 Key 由服务端生成，不能包含用户可见路径；重命名和移动只改元数据。
- Redis、Kafka、OpenSearch 均不是本次 MVP 的运行依赖。
- “生产 PostgreSQL/S3 适配器”表示适配器采用真实协议、超时、连接池和错误映射；
  受限于开发令牌身份边界，整个 MVP 仍只允许在隔离环境使用。

## 3. MUST

### 3.1 服务基础

- 提供进程启动、优雅停止、结构化配置、`GET /healthz` 和 `GET /readyz`。
- readiness 必须检查 PostgreSQL；启用真实对象存储时还必须进行无文件字节传输的轻量可达性检查。
- 所有 API 返回统一 JSON 错误结构，至少包含稳定错误码、消息和 `request_id`。
- 为受保护接口注入请求 ID、租户 ID、主体 ID；日志不得记录令牌、签名 URL 或对象存储密钥。
- 数据库 Schema 通过版本化迁移管理，空库可前进迁移到当前版本。

### 3.2 MVP 身份与租户边界

- 受保护接口必须要求 `Authorization: Bearer <opaque-token>`。
- Token 必须由服务端配置映射到固定的 `tenant_id` 和 `principal_id`；正式角色/ACL 属于 M2；
  客户端不能通过 `X-Tenant-ID`、请求体或 Token 自声明切换租户。
- 缺失或无效 Token 返回 `401`；跨租户资源统一按不存在处理，返回 `404`，避免资源枚举。
- 提供只读的当前租户发现接口，返回 Token 映射的租户和根目录 ID；接口不接受租户选择参数。
- `trusted-dev` 身份模式必须在显式生产/公网模式下拒绝启动，并在文档中标明仅限开发和验收环境。
- 所有 Repository 查询和写入都必须显式带 `tenant_id`，并有跨租户负向测试。

### 3.3 目录与文件元数据

- 支持创建目录、读取目录、列出直接子项、读取文件，以及对文件/目录进行重命名和移动。
- 目录列表使用稳定的 Keyset Cursor；默认 `limit=50`，最大 `limit=200`，禁止深度 `OFFSET`。
- 同一租户、同一父目录下，规格化后的活动名称必须唯一；冲突返回 `409 name_conflict`。
- 根目录由租户初始化流程确定，不能被移动、回收或改名。
- 移动目录时必须拒绝把目录移动到自身或其后代下。
- 普通文件只能由成功的上传完成事务创建；MVP 不提供绕过对象提交的“空文件元数据”接口。
- Blob 和文件版本不可变。MVP 不支持覆盖同名文件或版本历史 UI；同名上传返回冲突。

### 3.4 直传上传生命周期

- 使用状态机 `CREATED -> UPLOADING -> OBJECT_COMPLETED -> COMMITTED`，并支持 `ABORTED`、
  `EXPIRED`、`FAILED` 终态；非法迁移必须被拒绝。
- 创建会话时检查父目录、文件名、预期大小和 MIME 类型，生成与用户路径无关的对象 Key。
- 使用 S3 Multipart Upload，即使小文件也允许以单个最终分片完成；分片大小可配置，默认建议 8 MiB。
- 分片签名一次只授权指定会话、对象 Key、Part Number、HTTP 方法和短期 TTL。
- 完成请求必须校验分片号唯一且有序、ETag/校验信息、会话租户、过期时间和对象最终大小。
- 对提供者可返回的完整校验和进行验证；不支持完整校验和的后端必须记录 `checksum_status`，
  不能把客户端声明值描述为服务端已验证值。
- 完成请求必须幂等：重复提交返回同一文件结果，不得创建重复节点、版本、Blob 或重复扣减引用。
- 元数据提交在单个 PostgreSQL 事务中完成；对象完成但事务失败时保留可识别状态，供对账清理。
- 取消或过期会话必须尝试终止 Multipart Upload；清理操作可重复执行。
- HTTP API 不接收普通文件内容，且必须设置控制请求体上限。

### 3.5 下载授权

- 只为当前租户内、未回收、已提交的文件版本签发短期下载 URL。
- 签名必须限定对象 Key、`GET` 方法、过期时间和下载文件名；响应返回 `expires_at`，不返回存储凭证。
- 回收中、永久删除中、未提交上传或跨租户资源均不得获得下载授权。
- Range 和断点续传由 S3 兼容数据面承担，控制面不代理文件响应体。

### 3.6 回收站

- 支持文件和目录移入回收站、分页列出、恢复、永久清理。
- 回收目录时其后代不可从普通 Namespace 查询或获得下载授权。
- 恢复时校验原父目录和名称；父目录不存在或名称冲突返回 `409 restore_conflict`，不自动改名。
- 永久清理必须先提交元数据状态，再由幂等清理流程删除无引用对象；对象删除失败可重试，
  不能回滚为可见文件。
- 手动永久清理属于 MUST。回收保留期配置和自动到期清理作为一项完整维护能力属于 SHOULD；候选实现
  不声明自动保留或无人值守清理语义。

### 3.7 适配器与验证

- 提供 PostgreSQL Metadata Repository，实现租户过滤、事务、唯一约束和并发冲突映射。
- 提供 S3 兼容 Object Storage Adapter，并在 SeaweedFS S3 端点执行集成验证。
- 提供确定性的内存 Metadata Repository 和 Object Storage fake，供单元测试与故障注入使用。
- fake 必须遵守与真实 port 相同的状态和错误语义，不能成为第二套业务规则实现。
- 自动化测试至少覆盖成功路径、非法状态迁移、幂等重试、名称冲突、恢复冲突和跨租户访问。

## 4. SHOULD

- 维护并校验 OpenAPI 契约，给出可运行的 API 示例。
- 暴露 Prometheus 格式的请求量、延迟、错误率、上传状态和清理积压指标。
- 支持通过 `Idempotency-Key` 对创建目录和创建上传会话进行有限期去重。
- 使用数据库级乐观并发字段，令移动、重命名和恢复冲突可预测。
- 提供过期上传会话和回收站到期项的同进程维护任务；暂不拆独立 Worker 服务。
- 提供一套可复现的本地 PostgreSQL + SeaweedFS 集成环境和最小运维说明。
- 为文件名规格化、Cursor 编解码、对象存储错误映射和时钟边界做模糊或属性测试。
- 按 scope §9 全表执行百万节点/长时多端点暂定 SLO 负载（见 ADR-0010）；本轮以烟雾基线与
  100 并发会话作为 MUST。

SHOULD 若延期，必须在验收记录中写明原因、风险和对应 M2 任务，不能静默删除。

## 5. NOT NOW

下列能力明确排除在本次 MVP 之外：

- OIDC/OAuth2、企业 SSO、用户注册、组织管理和正式会话体系；这些属于 M2 生产身份接入。
- 公网部署承诺、完整 IAM/ACL、分享链接、外链密码、配额计费和审计导出。
- Web、移动端、Tauri 桌面端、文件系统监听和多端同步。
- 文件覆盖、版本历史、冲突副本、秒传、内容寻址分块、跨租户或租户内去重。
- Redis、Kafka/Redpanda、Outbox 消费链路、OpenSearch。
- 预览、转码、病毒扫描、OCR、AI 摘要、内容审核和通知。
- CDN、上传代理、TUS、WebDAV、服务端解密、水印和 DLP。
- 微服务拆分、gRPC 内部服务、多地域、元数据分片、纠删码和冷热分层编排。
- Ceph、OSS、COS 等提供者专属能力；只保证标准 S3 兼容 port，后续按需验证。
- 管理控制台、租户自助创建、计费、法律保留和正式 SLA。

## 6. API 目标契约

路径以 `/api/v1` 为前缀；确切字段由 API 设计文档和 OpenAPI 固化。下表只定义 MVP 的行为面：

| 方法与路径 | 行为 | 主要成功码 |
| --- | --- | --- |
| `GET /healthz` | 进程存活，不访问依赖 | `200` |
| `GET /readyz` | 依赖就绪检查 | `200` / `503` |
| `GET /api/v1/tenant` | 读取认证 Token 所属租户和根目录 ID | `200` |
| `POST /directories` | 在父目录下创建目录 | `201` |
| `GET /directories/{id}` | 读取目录元数据 | `200` |
| `GET /directories/{id}/children` | Cursor 分页列出直接子项 | `200` |
| `PATCH /nodes/{id}` | 重命名或移动文件/目录 | `200` |
| `GET /files/{id}` | 读取已提交文件元数据 | `200` |
| `POST /uploads` | 创建 Multipart 上传会话 | `201` |
| `GET /uploads/{id}` | 查询上传状态 | `200` |
| `POST /uploads/{id}/parts/sign` | 为指定分片签名 | `200` |
| `POST /uploads/{id}/complete` | 完成对象并提交文件 | `200` / `201` |
| `DELETE /uploads/{id}` | 幂等取消上传 | `204` |
| `POST /files/{id}/download-authorizations` | 签发短期下载 URL | `201` |
| `DELETE /nodes/{id}` | 把文件或目录移入回收站 | `204` |
| `GET /recycle-bin` | Cursor 分页列出回收站根项 | `200` |
| `POST /recycle-bin/{id}/restore` | 恢复文件或目录 | `200` |
| `DELETE /recycle-bin/{id}` | 同步执行引用安全的永久清理 | `204` |

统一错误语义至少包括：`invalid_request`、`invalid_cursor`、`unauthenticated`、`not_found`、
`name_conflict`、`invalid_state`、`idempotency_conflict`、`restore_conflict`、`revision_mismatch`、
`request_too_large`、`unsupported_media_type`、`dependency_unavailable` 和 `internal_error`。

## 7. 核心数据与不变量

目标模型至少包含：

- `tenant`：MVP 通过迁移或测试 fixture 预置，不提供管理 API。
- `file_node`：租户内文件/目录树、显示名、规格化名、当前版本、回收状态。
- `file_version`：不可变的文件版本，MVP 每个文件只有一个已提交版本。
- `blob`：不可变对象定位、大小、可选校验和、删除状态和引用状态。
- `upload_session` / `upload_part`：Multipart 标识、对象 Key、预期大小、状态、过期时间和完成结果。
- `recycle_entry` 或等价字段：回收根项、原父目录、删除时间和清理状态。

必须保持以下不变量：

1. 活动 Namespace 中 `(tenant_id, parent_id, normalized_name)` 唯一。
2. 所有资源标识查询同时受 `tenant_id` 约束。
3. `COMMITTED` 文件一定引用已记录的不可变 Blob；未提交会话在 Namespace 中不可见。
4. 对象 Key 不依赖用户可见路径，重命名、移动和回收不复制对象。
5. 完成上传的幂等键是上传会话 ID；一个会话最多产生一个提交结果。
6. 对象存储和 PostgreSQL 不做分布式事务，失败通过持久状态和幂等对账收敛。
7. 被回收目录的全部后代对普通查询和下载授权不可见。
8. 只有最后一个元数据引用被永久清理后，Blob 才可进入对象删除流程。

## 8. 受信任开发令牌的安全边界

本边界用于让垂直切片可运行，不是简化版生产认证：

- Token 使用高熵不透明值，通过 Secret/环境配置注入；仓库、日志和错误响应中不得出现真实值。
- 服务端保存 Token 到主体/租户的映射，请求端提交的任何租户字段都不能覆盖映射结果。
- Token 比较避免明显的时序泄漏；轮换通过替换配置和重启完成。
- 签名 URL 默认 TTL 15 分钟，上传会话默认 TTL 24 小时，二者都可缩短但不能由客户端任意延长。
- CORS 默认关闭；如果为验收 UI 开启，只允许显式来源列表。
- 服务只允许绑定回环或受控网络；显式生产/公网模式必须拒绝 `trusted-dev`。

M2 必须用 OIDC/OAuth2 替换此边界，校验 issuer、audience、签名、时间声明和主体映射，并完成正式
角色/权限设计。在 M2 之前不得将 MVP 宣传为公网可用或生产身份安全。

## 9. 暂定 SLO 与容量目标

以下均为**初始暂定目标**，用于约束实现和建立测量基线，不是对外 SLA，也不表示当前已经达到。
测量环境应为单 API 实例、同地域 PostgreSQL 与 SeaweedFS、预热 5 分钟、持续采样至少 10 分钟；
实际 CPU、内存、数据规模和依赖版本必须随结果归档。

> 分阶段边界（[ADR-0010](../adr/0010-mvp-slo-measurement-boundary.md)）：本轮 MVP MUST 仅要求
> 可复现的控制面烟雾基线与 ≥100 并发上传会话真实依赖证据。表中百万节点/长时负载目标为 SHOULD，
> 延期前不得勾选「已满足全部暂定 SLO」。

| 指标 | 暂定目标 | 测量边界 |
| --- | --- | --- |
| 控制面月可用性 | `>= 99.5%` | 仅计服务端可控失败；计划维护单独记录 |
| `healthz` 延迟 | p95 `<= 50 ms` | 50 RPS，不访问依赖 |
| 目录读取/列表延迟 | p95 `<= 200 ms` | 每页 50 项，Namespace 最多 100 万活动节点，50 RPS |
| 元数据写入延迟 | p95 `<= 300 ms` | 创建目录、移动、重命名、回收，20 RPS |
| 分片签名延迟 | p95 `<= 250 ms` | 50 RPS；不包含文件上传时间 |
| 上传完成控制请求 | p95 `<= 1 s` | 最多 1,000 个分片；不包含客户端传输时间 |
| 下载授权延迟 | p95 `<= 250 ms` | 50 RPS；不包含对象下载时间 |
| 控制面服务端错误率 | `< 1%` | 排除预期 `4xx`，持续 10 分钟 |
| 并发会话基线 | `>= 100` 个活动上传会话 | 无数据流经 API，状态无串租户或重复提交 |

文件吞吐量由客户端、网络和对象存储决定，不能计为 Go 控制面的 SLO。MVP 验收只验证直传、Range
能力可由数据面使用，以及控制面没有代理文件字节。

## 10. 默认限制

- 默认单文件上限：50 GiB，可通过服务端配置下调；不能由客户端提高。
- 默认上传会话 TTL：24 小时。
- 默认上传/下载签名 TTL：15 分钟。
- 后续自动回收维护策略的设计默认值：30 天；候选实现尚无生效的保留期配置。
- 默认目录页大小：50，最大 200。
- 默认控制请求体上限：1 MiB；完成分片清单可设置独立且有界的更高限制。

这些值属于 MVP 配置基线。修改影响安全、兼容性或状态机语义时，需要通过 ADR 或设计评审记录。
