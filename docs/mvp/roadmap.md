# 后端 MVP 实施路线

> 状态：规划基线。任务进度与完成声明必须以 [implementation-log.md](implementation-log.md) 和
> [acceptance.md](./acceptance.md) 的可复现证据为准，不能仅按代码存在或合并状态判断。

## 1. 里程碑总览

| 里程碑 | 目标 | 入口依赖 | 出口结果 |
| --- | --- | --- | --- |
| P0 设计与工程基线 | 固化边界、契约、port 和测试策略 | MVP 范围获确认 | 可评审的设计与可启动骨架 |
| P1 租户 Namespace | 打通身份边界、PostgreSQL 元数据和目录/文件查询 | P0 | 隔离的租户 Namespace 闭环 |
| P2 直传上传 | 打通 Multipart 签名、完成事务和失败收敛 | P1 | fake 数据面上的上传提交闭环 |
| P3 下载与回收 | 完成下载授权、回收、恢复和永久清理语义 | P2 | 完整用户主路径闭环 |
| P4 真实集成与发布门槛 | 接入 PostgreSQL + SeaweedFS，完成安全、性能和运维验证 | P3 | MVP 验收候选版本 |

主依赖链：

```text
P0 -> P1 -> P2 -> P3 -> P4 -> MVP Definition of Done
```

任务可以在里程碑内部并行，但不得绕过其依赖和出口条件。

## 2. P0：设计与工程基线

目标：先明确哪些行为必须一致，再开始业务实现。

| ID | 任务 | 产物 | 依赖 |
| --- | --- | --- | --- |
| P0-01 | 评审 MVP 范围、非目标、暂定 SLO 和完成定义 | `docs/mvp/` 基线 | 无 |
| P0-02 | 归档模块化单体、元数据、直传状态机、身份边界等关键 ADR | `docs/adr/` | P0-01 |
| P0-03 | 细化 API、错误模型、Cursor、幂等和签名协议 | 设计文档与 OpenAPI 草案 | P0-01, P0-02 |
| P0-04 | 定义 domain/application/port/adapter 依赖方向和包布局 | 模块设计 | P0-02 |
| P0-05 | 建立配置、请求 ID、统一错误、优雅停止、health/readiness 基线 | 服务骨架与测试 | P0-03, P0-04 |
| P0-06 | 定义单元、Repository 契约、集成和端到端测试夹具 | 测试设计与最小夹具 | P0-03, P0-04 |

P0 出口条件：

- 范围、关键 ADR 和详细设计之间没有未解释冲突。
- API 可以表达完整主路径和规定的失败路径。
- port 不泄漏具体 PostgreSQL 或 S3 SDK 类型到 domain/application。
- health、错误和配置基线有自动化测试，且构建检查可重复执行。

## 3. P1：租户身份与 Namespace

目标：以 PostgreSQL 为真相源，提供严格租户隔离的目录/文件元数据能力。

| ID | 任务 | 产物 | 依赖 |
| --- | --- | --- | --- |
| P1-01 | 实现受信任开发 Token 到租户/主体的服务端映射与生产模式防护 | Auth middleware 与负向测试 | P0-05 |
| P1-02 | 设计并实现首版 PostgreSQL 迁移、索引、唯一约束和根目录初始化 | 迁移与回滚/恢复说明 | P0-02, P0-04 |
| P1-03 | 实现 Metadata Repository port 和 PostgreSQL adapter | Repository 与契约测试 | P1-02, P0-06 |
| P1-04 | 实现确定性的内存 Repository fake 与故障注入点 | 测试 fake | P0-06 |
| P1-05 | 实现当前租户/根目录发现、创建/读取目录、读取文件、Cursor 列表、移动和重命名用例 | Tenant/Namespace API | P1-01, P1-03, P1-04 |
| P1-06 | 实现名称规格化、循环移动防护、并发冲突和跨租户测试 | 领域测试与集成测试 | P1-05 |

P1 出口条件：

- `401`、跨租户 `404`、名称冲突 `409` 和非法移动均有自动化证据。
- PostgreSQL 与 fake 通过同一组 Repository 契约测试。
- 目录列表只使用稳定 Cursor，测试覆盖翻页期间无重复的稳定排序语义。
- 移动和重命名不调用对象存储 port。

## 4. P2：签名直传与上传提交

目标：控制面协调上传，文件字节由客户端直接传到对象存储。

| ID | 任务 | 产物 | 依赖 |
| --- | --- | --- | --- |
| P2-01 | 定义 Object Storage port、能力标志、错误分类和不透明对象 Key 规则 | port 与契约测试 | P0-02, P0-04, P0-06 |
| P2-02 | 实现内存 Object Storage fake，记录调用且支持超时/失败注入 | 测试 fake | P2-01 |
| P2-03 | 实现上传会话和分片持久化、状态机、TTL 与非法迁移保护 | Upload domain/application | P1-03, P1-04, P2-01 |
| P2-04 | 实现创建上传、查询状态、分片签名和控制请求体限制 | Upload API | P1-01, P2-02, P2-03 |
| P2-05 | 实现完成对象、Stat/大小校验和单事务元数据提交 | Complete use case | P1-05, P2-03, P2-04 |
| P2-06 | 实现完成幂等、并发完成、事务失败后的可对账状态 | 幂等与故障测试 | P2-05 |
| P2-07 | 实现取消、过期会话扫描和 Multipart Abort 的幂等逻辑 | 清理用例 | P2-03, P2-04 |

P2 出口条件：

- fake 数据面上可完成创建会话、签名、模拟直传、完成并读取文件的垂直测试。
- 重复或并发完成同一会话只产生一个文件、版本和 Blob。
- API handler 没有接收或转发文件内容，fake 调用记录可证明字节路径绕过控制面。
- 依赖超时、对象完成后数据库失败、取消重试和会话过期均有确定性测试。

## 5. P3：下载授权与回收站

目标：完成文件读取的授权出口和可恢复删除语义。

| ID | 任务 | 产物 | 依赖 |
| --- | --- | --- | --- |
| P3-01 | 实现文件可下载性判断和短期 GET 签名 | Download use case/API | P2-05 |
| P3-02 | 实现回收文件/目录及后代可见性规则 | Recycle use case/API | P1-05, P2-05 |
| P3-03 | 实现回收站 Cursor 列表和严格恢复冲突处理 | Restore API 与测试 | P3-02 |
| P3-04 | 实现永久清理状态、引用判定和幂等对象删除 | Purge/GC 用例 | P3-02, P2-07 |
| P3-05 | 验证回收、恢复、永久清理过程中的下载拒绝与跨租户隔离 | 端到端负向测试 | P3-01, P3-03, P3-04 |

P3 出口条件：

- 活动文件可获得受限下载 URL，回收、未提交和跨租户资源不能获得授权。
- 回收目录后其全部后代从普通查询消失，恢复后重新可见。
- 恢复冲突不自动覆盖或改名；永久清理失败可重试且不会恢复可见性。
- 对象仅在没有有效元数据引用时进入删除流程。

## 6. P4：真实适配器、质量与验收

目标：在真实 PostgreSQL 与 SeaweedFS S3 端点上复现主路径，并满足发布门槛。

| ID | 任务 | 产物 | 依赖 |
| --- | --- | --- | --- |
| P4-01 | 完成 S3 兼容 adapter：Multipart、签名、Complete、Abort、Head、Delete | 真实 adapter 与契约测试 | P2-01, P2-06, P2-07, P3-01, P3-04 |
| P4-02 | 建立可复现的 PostgreSQL + SeaweedFS 集成环境和隔离测试数据 | 集成环境说明 | P1-03, P4-01 |
| P4-03 | 在真实依赖上运行上传、下载、回收、恢复、清理和重启持久性测试 | 端到端证据 | P3-05, P4-02 |
| P4-04 | 加固超时、连接池、优雅停止、日志脱敏、配置校验和 readiness | 运行时加固与测试 | P0-05, P4-02 |
| P4-05 | 执行暂定 SLO 负载基线和 100 并发会话测试 | 可复现负载报告 | P4-03, P4-04 |
| P4-06 | 完成 OpenAPI、迁移、配置和故障处理说明，关闭 MUST 验收项 | 发布文档与验收记录 | P4-03, P4-05 |
| P4-07 | 进行最终范围回归：确认没有把 NOT NOW 变成隐式依赖 | 评审记录 | P4-06 |

P4 出口条件：

- PostgreSQL + SeaweedFS/S3 兼容端点上的主路径和关键失败路径全部通过。
- 内存 fake 测试无需外部服务，且真实 adapter 与 fake 满足相同 port 契约。
- 暂定 SLO 有环境说明、原始命令、结果和偏差；未达到的 MUST 指标必须阻断完成。
- 所有 MUST 验收项有证据，SHOULD 延期项有明确记录，NOT NOW 没有成为运行依赖。
- 全局 Definition of Done 已逐项签核。

| 被依赖能力 | 消费任务 | 原因 |
| --- | --- | --- |
| 身份上下文 P1-01 | P1-05, P2-04, P3-01, P3-05 | 所有业务入口必须先确定租户 |
| PostgreSQL 事务 P1-03 | P2-03, P2-05, P3-02, P3-04 | Namespace、上传提交和删除共享一致性边界 |

## 8. 实施纪律

1. 每个任务先确认对应 ADR/设计和验收条目，再实现代码。
2. domain/application 测试优先使用内存 fake；adapter 契约和端到端测试使用真实依赖。
3. 每次数据库变更必须有迁移、索引说明和向前兼容评估。
4. 每次状态机变更必须补全重复请求、超时、并发和依赖失败测试。
5. 不为了提前建设 M2 而引入 Redis、消息系统、搜索或微服务框架。

## 9. 风险与缓解

| 风险 | 早期信号 | MVP 缓解措施 |
| --- | --- | --- |
| S3 兼容实现差异 | 签名、Checksum 或 Multipart 行为不一致 | port 暴露能力标志；SeaweedFS 做固定集成验证；不虚报未验证校验和 |
| 对象与数据库双写失败 | 对象已完成但文件不可见 | 持久状态机、幂等完成、对账清理和故障注入测试 |
| 租户条件漏写 | 仅按资源 ID 查询 | Repository API 强制 tenant 参数，同一套跨租户契约测试 |
| 目录删除/恢复复杂 | 后代可见性或名称冲突不一致 | 回收根项语义、统一查询过滤、严格冲突而非自动改名 |
| fake 与真实实现漂移 | 单元测试通过但集成失败 | 共享 port 契约测试，P4 必须跑真实依赖主路径 |
| MVP 被误当生产认证 | 服务被暴露到公网 | trusted-dev 生产模式拒绝启动，文档和配置显式警告，OIDC 固定进入 M2 |
| 范围膨胀 | 提前引入同步、分享、预览 | NOT NOW 清单和 P4-07 范围回归 |

## 10. M2 入口

MVP 完成后才进入 M2。M2 首要工作是 OIDC/OAuth2 生产身份接入、正式主体/角色/权限模型、
安全评审和部署加固；随后再评估分享、配额、审计、Outbox Worker、同步与预览。M2 不属于 P0-P4，
也不能作为跳过本次 MVP 验收项的理由。
